# Формирование CIFF/XML в Glyph 2.3.0 и установленном ClariSoft

Дата: **21.10.2026**. Сначала выполнен аудит; алгоритмы приложения и пользовательские CIFF в рамках этой работы не исправлялись.

## Основной результат

**ImageWidth/ImageHeight и MaxImageWidth/MaxImageHeight описывают разные размеры.** MaxImage* задаёт рабочую область конкретного SubImage. В редакторе ClariSoft по ней строятся фон и сетка. Image* хранит размер изображения; отдельный алгоритм приложения пересчитывает его по печатным полям. Обычная запись XML через CiffMgr эти размеры не пересчитывает.

**В Print Preview ClariSoft обе пары участвуют одновременно:** Best Fit рассчитывает масштаб по Image*, а прямоугольник бумаги — по Max* с fallback на Image* при нуле и ограничением по capabilities. Поэтому изменение Image* может изменить экранный масштаб текста без изменения Font, X/Y или W/H.

У текущего Glyph выбор рабочей области и обычный расчёт Image* в целом соответствуют найденным путям ClariSoft. Найдены отдельные расхождения: поведение после удаления последнего печатного поля, ограничения нулевых размеров, разрешение YRes, неподдержанные преобразования всей страницы и свойства расширенных источников. Большинство дополнительных пустых и нулевых XML-тегов Glyph относится к форме записи, а не к доказанным причинам изменения шрифта или позиции.

**Сохранить неизвестный тег в импортированном XML и воспроизвести его поведение в предпросмотре — разные возможности.** Glyph часто делает первое, но не второе. Также отдельно рассматриваются новое поле, обычное сохранение импортированного поля и перестройка его структуры.

## 1. Четыре тега размеров

Для исследованных профилей с миллиметровыми координатами одна внутренняя единица CIFF равна **0,01 мм**: 1600 = 16 мм. В native модели это Units=U_HMM(0), используемый по умолчанию. Существует и Units=U_DOTS(1), где нужно учитывать точки и разрешение; миллиметровую формулу нельзя переносить на него. Glyph сейчас использует INTERNAL_PER_MM=100 и не моделирует Header/Units: исходный тег может сохраниться, но его смысл не применяется при отображении.

| Тег | Назначение | ClariSoft | Текущий Glyph |
|---|---|---|---|
| ImageWidth | Сохранённая ширина изображения / рассчитанный правый предел печатных объектов от X=0 | Отдельное свойство модели. Обновляется алгоритмом приложения; writer пишет текущее значение. Используется Print Preview Best Fit | При неизменной импортированной печатной геометрии сохраняет исходное значение; после изменения пересчитывает |
| ImageHeight | Аналогичный нижний предел от Y=0 | Аналогично ImageWidth | Аналогично ImageWidth |
| MaxImageWidth | Ширина рабочей области данного SubImage | Используется для фона/сетки редактора и проверки вписывания | Определяет ширину белого листа/сетки; имеет приоритет над ImageWidth |
| MaxImageHeight | Высота рабочей области данного SubImage | Используется для фона/сетки редактора и проверки вписывания | Определяет высоту белого листа/сетки; имеет приоритет над ImageHeight |

**MaxImage* не обязательно равно аппаратному максимуму принтера.** Можно выбрать рабочую область меньше аппаратного предела. Capabilities принтера и MaxImage* — отдельные ограничения.

### Почему Image* нельзя считать автоматически актуальным bounding box

Оригинальный CiffMgr хранит и пишет Image* и MaxImage* независимо. Свежие пробы подтвердили:

- AddSubImage(1600,2400) инициализирует **обе** пары как 1600×2400 даже без полей.
- Добавление поля, в том числе за Max*, само по себе не меняет эти значения.
- Load → save сохраняет нулевые, отрицательные и противоречивые размеры на уровне модели; это не означает, что такой документ пригоден для UI или печати.
- AutoSize=1 само по себе не запускает пересчёт при Load → save.

Следовательно, фраза «Image* — всегда точный размер содержимого файла» слишком сильна. Это **сохранённый размер**, который становится вычисленным размером содержимого после соответствующего шага приложения.

### Как ClariSoft пересчитывает Image*

Свежая декомпиляция EXE:

| Функция | Найденное поведение |
|---|---|
| 00E6600F | Перебирает cached fields, учитывает только FieldDisplayed !=0, накапливает максимальные правую/нижнюю границы с начальным 0 |
| 00EB59A2 | Получает ICiffField.FieldDisplayed |
| 00E61D8E | Получает прямоугольник поля; при 90°/270° W/H меняются местами |
| 00E67CDB | Записывает результат в ImageWidth/ImageHeight |
| 00E2D699 → 00E2DE4E | Для редакторской ветви строит фон/сетку по прямоугольнику (0,0,MaxImageWidth,MaxImageHeight) |
| 00EB1A01 → 00EAEAE0 | Проверяет видимые поля относительно Max*, с квантованием через printer capabilities |
| CLPrintPreview.ocx!3F418143 | Best Fit читает ImageWidth/Height и вычисляет масштаб печатного preview |
| CLPrintPreview.ocx!3F412CE9 → 3F412846 | Размер бумаги из Max*, при нуле каждой оси fallback на Image*; перевод в printer dots, ограничения capabilities, рисование прямоугольника |

Для обычных полей с целочисленной геометрией основной расчёт такой:

```text
ImageWidth  = max(0, x + ширина_после_поворота для всех печатных полей)
ImageHeight = max(0, y + высота_после_поворота для всех печатных полей)
```

Минимальные X/Y не вычитаются. Поле X=100, W=500 даёт правую границу600, а не500. Скрытый источник с Displayed=0 не увеличивает размер, даже если используется в DataMatrix. Это расчёт прямоугольников полей, не чёрных пикселей букв.

У Glyph основной расчёт совпадает для обычной допустимой геометрии. Отличия пустого набора/минимума и специальных native штрихкодов перечислены ниже. Код Glyph: [calculateImageBounds](C:/Users/GigaGeorge/Desktop/willow-react-vite-test_1.4.0/public/modules/30-rendering.js:403), [syncUsedImageSizeFromPrintableFields](C:/Users/GigaGeorge/Desktop/willow-react-vite-test_1.4.0/public/modules/30-rendering.js:443).

Отдельный native сценарий — профиль типа Line: в 00E2B99E превышение ImageWidth над MaxImageWidth может расширить MaxImageWidth и рабочий размер view. Это условная ветвь, а не правило всех принтеров; симметричная запись MaxImageHeight в этой функции не найдена.

### Что происходит при изменении значений

| Сценарий | ClariSoft | Glyph |
|---|---|---|
| Image600×700, Max2000×3000 | Фон редактора берётся из Max*: 20×30 мм | Лист20×30 мм; неизменное сохранение сохраняет Image600×700 |

| Поле сдвинуто внутри листа | Вызов aggregate меняет Image*, Max* отдельно | После изменения печатной геометрии меняет Image*, Max* сохраняет |
| Сдвинуто только скрытое поле | В aggregate не участвует | Image* не меняется |
| Удалено последнее печатное поле / все скрыты | Сам aggregate возвращает0×0 | При пересчёте остаются прежние Image*: подтверждённое отличие |
| Image* больше Max* | Модель допускает; UI-проверка вписывания — отдельный этап | Неравенство само по себе не запрещено. Неизменный импорт за областью допускается; новый/отредактированный выход блокируется |
| Max* отсутствует | Native reader использует соответствующее Image* | Положительный Image* становится размером листа; недостающие Max* восстанавливаются |
| ImageWidth или ImageHeight отсутствует | Load возвращает 0x80030104, STG_E_OLDFORMAT | Parser допускает открытие; без восстановления корректных Image* save может быть отвергнут |
| Image*=0, Max*>0 | COM Load/save сохраняет нули; корректность конкретного GUI-пути отдельно | Лист можно показать по Max*, но validator требует положительные Image* |
| Max*=0, Image*>0 | В editor background используется сам Max*. Print Preview paper extent использует Image* для нулевой оси | Glyph выбирает положительный Image* для листа; это отдельное отличие fallback редакторского пути |
| AutoSize=1 | Load/save сохраняет флаг и размеры; автоматический пересчёт writer не выполняет | Флаг сохраняется сырым XML; собственной AutoSize-модели нет |

**Вывод о предпросмотре:** менять Image* ради изменения размера белого листа неверно для исследованного редакторского пути. Менять Max* ради увеличения букв тоже неверно: физический размер шрифта задают параметры Font и геометрия поля. Эти четыре тега не меняют сохранённые X/Y и не заменяют ModuleSize DataMatrix. Однако Best Fit может изменить общий экранный масштаб из-за Image*.

## 2. Формирование шаблона: разные этапы

В ClariSoft восстановлена цепочка:

```text
CreateField + профиль → Resolve/UpdateData → CalculatedData
→ CalculateSize/Resize → геометрия → условные printer conversions
→ обновление размера изображения → ClSt → XML writer
```

Это логические этапы. Не все вызовы обязательно выполняются при каждом Save: режим, компонент и capabilities определяют конкретный маршрут. Writer читает уже подготовленную модель; он не исправляет её автоматически по имени тега или CalcData.

Glyph использует собственные фабрики, resolver поддержанных источников, native text measurement и специальный DataMatrix calculator. Затем готовит единый snapshot CalcData для XML и ClSt, выполняет консервативные патчи и validation.

| Путь Glyph | Что происходит | Следствие |
|---|---|---|
| Новое поле | buildFieldXmlOneLine создаёт структуру из модели | Неподдержанные свойства не появятся |
| Обычное сохранение импорта | Изменяются известные части исходной XML-строки | Большинство неизвестных узлов/атрибутов сохраняется |
| Изменение структуры DataMatrix | При structureDirty список Object перестраивается | Свойства прежних объектов, не представленные в модели, могут потеряться |

В UI редактируется первый SubImage; остальные сохраняются в исходном документе. У обычного текста модель ориентирована на первый Data/Object; для DM читается список сегментов. Наличие исходных дополнительных объектов не означает полной поддержки их вычислений и редактирования.

Основные native writer: CiffMgr!68129209 → 6812DC1C; Header68129BFC; SubHeader6812C2CA; Field68128924; Object68126560; Text6812CCCE; Font6812D1DE; Barcode68124AFE. Адреса — preferred VA исследованных файлов.

### Условия записи Header/SubHeader

| Свойство | Оригинальный writer | Glyph |
|---|---|---|
| ImageWidth/Height, MaxImageWidth/Height | Все четыре пишутся всегда из свойств модели, включая0 | Создаются/восстанавливаются при сохранении, с собственным validation |
| XRes | Пишется всегда | Пишется; участвует в модели |
| YRes | Только если отличается от XRes | Импортированный тег сохраняется, новый не создаётся; preview его не читает |
| AutoSize | Только если не default | Импорт сохраняется; полноценной модели нет |
| ImageRotation/Mirror/Inverse | По значениям и внутренним enable-флагам | Сырые импортированные теги сохраняются |
| CurrentOrientation | Условный enum native writer, не универсально обязательный нулевой узел | Новая/обязательная часть каркаса Glyph |
| SubHeader/@PrinterType | Независимое свойство; при отличии от File.DesignedFor | Импорт сохраняется, в новом каркасе отсутствует |
| Header/@DesignedFor/DesignedWith/OverrideAll | Default Generic/CLARiSOFT/0 опускаются | Новый каркас содержит DesignedFor; импортированные метаданные сохраняются |
| Header/Units и расширения, LastDownloaded/LastUpdated, LineID | Условные метаданные/extension-пути | Нет полной модели создания и обновления |

Порядок native SubHeader: ImageWidth → ImageHeight → ImageRotation? → MaxImageWidth → MaxImageHeight → AutoSize? → ImageMirror? → ImageInverse? → XRes → YRes? → CurrentOrientation? → LastUpdated?. Отсутствие optional узла часто означает default, а не отсутствие функции принтера.

### Тип поля, тег и источник данных

Имя Field/@Name, строка FldType, семейство Text/Barcode/Graphic, CLSID обработчика и тип каждого Data/Object — **разные уровни модели, согласуемые при создании**. Имя BOX_COUNTER не включает счётчик; PRODUCT_DATE не превращает пользовательскую строку в вычисляемую дату. Внутренний EDataType и записанный в XML ClearStyleDataType — разные enum: ветвь VarText/SrcField/Counter нельзя выбирать только по одному числу XML DataType.

| Сценарий | Нужная структура / смысл | Что не добавляется автоматически |
|---|---|---|
| Постоянный текст | Text, Object с DataType0; Default, если значение непустое | VarText, FixedLen, CounterText |
| Ввод оператором на принтере | Источник VariableText → VarText; у исследованных рецептов Static0, DataType0 | FixedLen только по факту пользовательского ввода |
| Ограничение числа символов | MaxNoOfChars при значении !=0 | FixedLen только из наличия максимума |
| Фиксированная длина | Явно включён FixedLength → FixedLen; padding по отдельным настройкам | Нельзя выводить из имени SN/GTIN или длины текущей строки |
| Текущая дата / время | Parse1, DataType2/1, Default содержит формат | VarText и FixedLen не обязательны |
| Дата со смещением | OffsetDate/SrcOffset со ссылкой на Header DateOffset | Writer не создаёт правильное правило смещения из имени поля |
| Автоматический счётчик | CounterText + используемые SubCnt с параметрами счёта | Имя BOX_COUNTER не является таким источником |
| Ссылка на поле | SrcField/@SrcFieldName; условные substring/select настройки | Не надо дублировать конфигурацию источника как VarText |

| CalcData | Если непустой после фильтра недопустимых controls |
| LoggedField | Пропустить только при точной строке Not Logged; пустое значение даёт пустой тег |
| Clip | Только при наличии clipping rectangles |
| Object/@Index | Если !=0; исходная коллекция сортируется по Index |
| Object/@Static, @Parse | Если !=1 и !=0 соответственно |
| Object/@EqRef, @Param | При ненулевом значении и поддержке соответствующего интерфейса |
| Object/@Reference | При поддержке интерфейса, включая пустую строку |
| DataType | Всегда |
| Locale, Calendar | При отличии от EN-GB и1 соответственно |
| Encryption | Только непустой |
| MaxNoOfChars | Если !=0 |
| Default | Только непустой; CDATA |
| FixedLen | Если FixedLength включён; пустой FixedLen допустим и значим |
| PadChar, PadMode | Только если не пробел U+0020 и не default0 соответственно |
| VarText/Prompt, Mask, UserEnterData | Только непустые; сам VarText может быть пустым |
| VarText/PromptAtCoder, ResetOnSel | Если !=1 и !=0 соответственно |
| ListData | При наличии списка/его источника, не для любого пользовательского ввода |

Запрещённые controls удаляются только для XML CalcData; TAB/LF/CR сохраняются с нормализацией MSXML. Текущий Glyph уже имеет этот фильтр и подготовку raw snapshot для ClSt.

**Пустые теги нельзя удалять по общему правилу.** Например, пустой Default native опускает, но SrcSQL пишет даже пустым; FixedLen/VarText могут быть значимыми пустыми контейнерами; HR/HRFont и ClrStCntType также могут быть пустыми в оригинальном результате.

### Шрифты, штрихкоды и счётчики

| Область | Native defaults и условия |
|---|---|
| Text/Font | Опускаются Arial, Family32, Pitch13, PitchResolution1, XMag100, YMag100, TTSize1, TxtDir0, CharSpace0 |
| Text | Bold/Italic/DblSpace — по флагам; Block — по отдельному признаку BlockText; Escapement/FixedWidth/MultiStroke — по дополнительным условиям типа/extension |
| Barcode | BcH всегда из отдельного свойства Barcode.Height; HR/HRFont создаются; Mag/MagRnd опускаются при1000/50, QuietMargin при1 |
| DataMatrix | ECCType опускается при5, ModuleSize при100, SymbolSize при Auto0; остальные символогии имеют собственные feature masks |
| CounterText | Rollover/PrnPerCnt/RolloverError опускаются при1; ResetOnSel/PromptWith/ResetSource при0; ParentCounter опускается при пустой строке |
| SubCnt | Пишутся объекты с Used!=0; Significance и NoOfChars — всегда; StartVal/EndVal/StepSize опускаются при0/9999/1; ClrStCntType пишется даже пустым |

Уточнение прежней спецификации: условие включения SubCnt — **Used!=0**, а не непосредственная проверка NoOfChars. Вызов vtable+0x7C подтверждён typelib.

Pitch10 в новых партионных шаблонах — явное требование пользователя. Его необходимо записывать: отсутствие Pitch означает native13. Пустой Font не означает «пиксельный шрифт». Способ экранной отрисовки и настройки CIFF — разные уровни.

Для Party: C1(~101), GTIN2(14 нулей), C3(11), PRODUCT_DATE(6 нулей), C2(10), SN(10 нулей, максимум12); со счётчиком C4(21), BOX_COUNTER(5 нулей, максимум5). GTIN2/PRODUCT_DATE/SN/BOX_COUNTER — FixedText+VarText. FixedLen у SN может дополнить исходные10 символов до12 в CalculatedData. Это не ошибка порядка и не основание заменить BOX_COUNTER на CounterText.

## 5. Что влияет на совпадение предпросмотра

Для совпадения белого листа обычного editor прежде всего нужны одинаковые MaxImage*. При сравнении с Print Preview дополнительно учитываются fallback/capabilities и режим масштаба Best Fit, зависящий от Image*. Для совпадения текста нужны совпадающие источник/CalculatedData, Font/Face/Pitch/PitchResolution/XMag/YMag/стили, X/Y/W/H, Orientation и разрешение используемого профиля. Для DataMatrix — порядок и значения Object, ModuleSize/SymbolSize/QuietMargin и согласованная геометрия/BcH.

Ни одна пара Image*/Max* не заменяет эти настройки. Скрытый большой helper может выглядеть заметным в редакторе Glyph и не участвовать в печатном размере; правильность здесь определяется Displayed и связями Data, а не только положением видимого на экране текста.

Векторный preview Glyph содержит контуры только для экрана. В CIFF сохраняются параметры поля и шрифта, а не SVG. Оригинальный bitmap preview может иметь другие пиксельные границы и hinting при тех же метрических размерах.
